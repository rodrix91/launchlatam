Como receber Pix em um app feito no Lovable (Mercado Pago e alternativas)

Resposta curta: para receber Pix num app feito no Lovable, crie o pagamento no servidor (uma Edge Function do Supabase) chamando POST /v1/payments do Mercado Pago com payment_method_id: "pix", mostre ao comprador o QR Code e o Pix Copia e Cola que voltam na resposta e libere o acesso só quando o webhook, com assinatura validada, confirmar o status approved. O access token nunca vai para o frontend.

O Lovable tem pagamentos integrados com Stripe ou Paddle e também aceita a sua própria conta Stripe (documentação do Lovable). Para Pix, o caminho mais direto para quem vende no Brasil costuma ser o Mercado Pago. Abaixo está o passo a passo, com as alternativas no final.

O que você precisa antes

  • Uma conta de vendedor no Mercado Pago com chaves Pix cadastradas. Sem chave Pix, a opção não aparece (pré-requisitos do Mercado Pago).
  • Uma aplicação criada em Suas integrações, com a public key e o access token de teste.
  • Um backend: o Supabase conectado ao seu projeto do Lovable, onde vão a Edge Function e os segredos.

Passo 1: guarde o access token como segredo

O access token cria cobranças e lê pagamentos da sua conta. Salve-o como segredo do Supabase (por exemplo MP_ACCESS_TOKEN) e use-o só dentro de Edge Functions. No navegador vai, no máximo, a public key. Se o token já apareceu no código ou no repositório, gere outro no painel do Mercado Pago antes de seguir.

Passo 2: crie o pagamento Pix numa Edge Function

A documentação do Mercado Pago mostra o pagamento Pix como um POST em /v1/payments com payment_method_id: "pix", o e-mail do comprador e o cabeçalho obrigatório X-Idempotency-Key, que evita cobrança duplicada se a requisição for repetida (documentação Pix do Mercado Pago).

// supabase/functions/criar-pix/index.ts
Deno.serve(async (req) => {
  const { email, pedidoId } = await req.json();
  const PRECO = 49.90; // o preço é definido aqui, nunca no navegador
  const r = await fetch("https://api.mercadopago.com/v1/payments", {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${Deno.env.get("MP_ACCESS_TOKEN")}`,
      "Content-Type": "application/json",
      "X-Idempotency-Key": crypto.randomUUID(),
    },
    body: JSON.stringify({
      transaction_amount: PRECO,
      description: "Plano Pro",
      payment_method_id: "pix",
      external_reference: pedidoId,
      payer: { email },
    }),
  });
  const p = await r.json();
  const t = p.point_of_interaction?.transaction_data;
  return Response.json({ id: p.id, status: p.status,
    qr_code: t?.qr_code, qr_code_base64: t?.qr_code_base64, ticket_url: t?.ticket_url });
});

Por padrão o código Pix vence em 24 horas. Você pode mudar isso com date_of_expiration, entre 30 minutos e 30 dias a partir da emissão (fonte). Para um app com assinatura ou acesso imediato, um prazo curto evita pedidos “pendentes” acumulados.

O Mercado Pago também documenta o Pix na Orders API, mais nova, com payment_method.type = "bank_transfer" (documentação da Orders API). A lógica é a mesma: criar no servidor, exibir o QR e confirmar pelo webhook.

Passo 3: mostre o QR Code e o Copia e Cola

A resposta do pagamento chega com status pending e status_detail pending_waiting_transfer, e traz três coisas em point_of_interaction.transaction_data: qr_code_base64 (a imagem), qr_code (o texto do Pix Copia e Cola) e ticket_url (uma página do Mercado Pago com tudo pronto). No Lovable, peça na conversa um componente que receba esses campos:

<img src={`data:image/jpeg;base64,${qr_code_base64}`} alt="QR Code Pix" />
<input readOnly value={qr_code} /> <button>Copiar código Pix</button>

Quem paga pelo celular normalmente prefere o Copia e Cola; quem está no computador escaneia o QR.

Passo 4: confirme o pagamento pelo webhook, não pela tela

O Pix é pago fora do seu app, no banco do comprador. Por isso a confirmação tem que vir do servidor:

  1. Configure em Suas integrações → Webhooks uma URL que aponte para outra Edge Function e copie a assinatura secreta.
  2. Em cada notificação, valide o cabeçalho x-signature (formato ts=...,v1=...): monte id:<data.id>;request-id:<x-request-id>;ts:<ts>;, calcule o HMAC-SHA256 com a sua chave secreta e compare com v1. Se não bater, responda 401 (documentação de webhooks).
  3. Com a assinatura válida, consulte GET /v1/payments/{id} e só libere o acesso se o status for approved. Trate a notificação como um aviso, e a consulta à API como a verdade.
  4. Seja idempotente: a mesma notificação pode chegar mais de uma vez. Guarde o id do pagamento e não ative o plano duas vezes (guia do SDK oficial).

Guarde o pagamento numa tabela do Supabase com RLS ativado, para que cada usuário veja só os próprios pedidos. Se você ainda não revisou isso, veja o nosso guia de RLS no Supabase para apps do Lovable (em espanhol).

Passo 5: teste antes de ir para produção

Use as credenciais e contas de teste do Mercado Pago e faça uma compra de teste com Pix antes de trocar para as credenciais de produção. O Mercado Pago tem uma seção específica para isso (“Realizar uma compra teste com Pix”) na documentação do Checkout Transparente.

Alternativas ao Checkout Transparente

  • Checkout Pro do Mercado Pago. O comprador é levado ao ambiente do Mercado Pago, que já oferece Pix, cartão e boleto. Dá menos trabalho de interface; você ainda precisa do webhook para confirmar o pagamento. Temos um guia de Checkout Pro no Lovable (em espanhol).
  • Stripe com Pix. Contas Stripe no Brasil aceitam Pix avulso com liquidação em BRL; empresas fora do Brasil (por exemplo EUA ou países da Europa) também podem receber Pix de clientes brasileiros. Nesse caso o cliente paga IOF de 3,5% por padrão, e o Pix Automático (recorrente) não está disponível para empresas sediadas no Brasil (documentação da Stripe). Como o Lovable conecta a sua própria conta Stripe, essa é uma opção se você já tem Stripe.
  • Atenção se você não está no Brasil. A lista de países com conta Stripe que aceita Pix não inclui Bolívia, Paraguai nem Argentina (fonte). Para vender para o Brasil a partir desses países, compare as opções no nosso artigo sobre cobrar sem Stripe (em espanhol).

Erros que mais vemos

  1. Access token no frontend. Qualquer pessoa que abrir o código do site consegue usá-lo.
  2. Preço enviado pelo navegador. O valor tem que ser definido na Edge Function.
  3. Liberar o acesso na tela de “obrigado”. Sem webhook validado, qualquer um chega nessa tela sem pagar.
  4. Webhook sem validar x-signature. Abre a porta para notificações falsas.
  5. Sem X-Idempotency-Key. Um clique duplo pode gerar dois pagamentos.

Perguntas frequentes

Como recebo Pix num app feito no Lovable?

Crie o pagamento numa Edge Function do Supabase com POST /v1/payments do Mercado Pago e payment_method_id pix, mostre o qr_code_base64 e o qr_code (Copia e Cola) que voltam na resposta e libere o acesso só quando o webhook, com a assinatura x-signature validada, confirmar o status approved.

Quanto tempo vale um código Pix do Mercado Pago?

Por padrão, 24 horas. Dá para mudar com o campo date_of_expiration, entre 30 minutos e 30 dias a partir da emissão do pagamento.

Posso usar Stripe para receber Pix?

Sim, se a sua conta Stripe for de um país suportado (Brasil, EUA, Canadá, vários da Europa, Austrália ou Singapura). Fora do Brasil, o cliente brasileiro paga IOF de 3,5% por padrão. Bolívia, Paraguai e Argentina não estão na lista.
