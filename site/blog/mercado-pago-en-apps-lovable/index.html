Cómo cobrar con Mercado Pago en una app hecha con Lovable (sin exponer tus claves)

Lovable trae integraciones nativas con Stripe y Paddle. Si vivís en Argentina, Chile, Colombia, Perú o Uruguay, o si tus clientes pagan con Mercado Pago, eso no alcanza. Esta guía muestra cómo integrar Mercado Pago Checkout Pro en una app de Lovable con Supabase, sin dejar tu clave secreta en el navegador.

La regla de oro: dos claves, dos lugares

Mercado Pago te da dos credenciales en Tus integraciones → Credenciales:

  • Public key (empieza con APP_USR- y es corta): puede ir en el frontend.
  • Access token (también empieza con APP_USR-, pero es larga): es secreta. Con ella se puede crear cobros y leer pagos de tu cuenta. Nunca va en el código de React.

El error más común en apps hechas con IA es pedirle al asistente “integrá Mercado Pago” y que pegue el access token en un archivo del frontend. Cualquier visitante lo puede leer abriendo las herramientas del navegador.

Paso 1: guardar el access token como secreto en Supabase

En tu proyecto de Supabase, andá a Edge Functions → Secrets y creá MP_ACCESS_TOKEN. También podés hacerlo desde la terminal:

supabase secrets set MP_ACCESS_TOKEN=APP_USR-xxxxxxxx

Paso 2: una Edge Function que crea la preferencia de pago

Checkout Pro funciona con “preferencias”: tu servidor le dice a Mercado Pago qué se vende y cuánto cuesta, y Mercado Pago devuelve un link de pago. El precio se define en el servidor, no en el navegador, para que nadie pueda cambiarlo.

// supabase/functions/crear-pago/index.ts
Deno.serve(async (req) => {
  const { planId } = await req.json();
  const PLANES = { pro: { title: "Plan Pro", price: 9900 } }; // precio en tu moneda
  const plan = PLANES[planId];
  if (!plan) return new Response("Plan inválido", { status: 400 });
  const r = await fetch("https://api.mercadopago.com/checkout/preferences", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${Deno.env.get("MP_ACCESS_TOKEN")}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      items: [{ title: plan.title, quantity: 1, unit_price: plan.price, currency_id: "ARS" }],
      back_urls: { success: "https://tuapp.com/gracias" },
      notification_url: "https://TU-PROYECTO.supabase.co/functions/v1/webhook-mp",
    }),
  });
  const pref = await r.json();
  return Response.json({ url: pref.init_point });
});

En el frontend, el botón “Pagar” solo llama a esta función y redirige a url.

Paso 3: confirmar el pago con un webhook (no con la URL de regreso)

Que el usuario vuelva a /gracias no prueba que pagó: cualquiera puede escribir esa URL. La fuente de verdad es la notificación que Mercado Pago envía a tu notification_url. En el webhook:

  1. Leé el id del pago que llega en la notificación.
  2. Consultá GET https://api.mercadopago.com/v1/payments/{id} con tu access token.
  3. Si status es approved, activá el plan del usuario en tu tabla.
  4. Validá la firma del encabezado x-signature con la clave secreta de webhooks que te da Mercado Pago, para descartar notificaciones falsas.

Paso 4: proteger la tabla de suscripciones

Si guardás el plan del usuario en una tabla subscriptions, activá Row Level Security y dejá que solo la Edge Function (con la clave de servicio, del lado del servidor) pueda escribir. Si no, un usuario podría marcarse a sí mismo como “pro” desde el navegador.

alter table public.subscriptions enable row level security;
create policy "leer la propia" on public.subscriptions
  for select using ((select auth.uid()) = user_id);
-- sin políticas de insert/update: solo el servidor escribe

Checklist final

  • El access token está solo en secretos de Supabase.
  • El precio se define en el servidor.
  • El plan se activa por webhook, no por la URL de regreso.
  • La tabla de suscripciones tiene RLS y nadie puede escribirla desde el navegador.
  • Probaste con las credenciales de prueba antes de pasar a producción.
